# Glossary — Fabric concepts (DP-700)

Core concepts needed across all three exam areas. Check via MCP before relying on a term if it feels outdated — Fabric evolves quickly.

- **OneLake** — one logical data lake for the whole organization ("OneDrive for data"). Every Fabric item stores its data in OneLake. No need to copy data between engines.
- **Lakehouse** — stores structured and unstructured data in Delta Parquet format. Development mainly with Spark (notebooks). Every lakehouse automatically gets a read-only **SQL analytics endpoint**.
- **Warehouse** — a traditional SQL data warehouse on top of Fabric. Full T-SQL (DDL/DML/DQL), ACID transactions, multi-table transactions. Development in T-SQL. Data is also stored in Delta format in OneLake.
- **SQL analytics endpoint** — a T-SQL interface automatically generated for every lakehouse, warehouse, database, and mirrored database. The Lakehouse's endpoint is **read-only** (no DML, limited DDL — views/TVFs allowed); Warehouse's own endpoint supports full T-SQL. Both use the same engine as Warehouse.
- **Lakehouse vs. Warehouse — decision criteria**: Lakehouse = data engineering, data science, medallion architecture, a Spark-first team, unstructured + structured data. Warehouse = BI reporting, dimensional modeling, a SQL-first team, need for multi-table transactions. Common pattern: load/transform in Lakehouse with Spark → expose curated data from Warehouse for SQL reporting.
- **OneLake shortcut** — a reference to data located elsewhere (another workspace, ADLS Gen2, S3, Dataverse, Iceberg sources…) without copying it. The data appears local within OneLake. Open formats only (e.g. Delta). Works at the table/folder/file level.
- **Mirroring** — brings an entire external database/catalog into Fabric without a separate ETL step. Two mechanisms depending on the source: **database mirroring** (continuously replicates the data into Delta format, e.g. Azure SQL DB, Cosmos DB, Snowflake, PostgreSQL) and **metadata mirroring** (only syncs the catalog's metadata and uses shortcuts to reach the data, e.g. Azure Databricks Unity Catalog). **Open mirroring** = a public API that lets anyone write change data directly into a mirrored-database item.
- **Shortcut vs. mirroring — decision criteria**: use a shortcut when the data is already in an open format and a reference is enough (zero-copy, no separate copy of your own). Use mirroring when an entire external operational database needs to be brought into Fabric as a unit, or when the source is in a proprietary format (in which case mirroring is the only option). The two can be combined: "mirror once, consume everywhere" — one workspace mirrors the source, other workspaces shortcut to the mirrored data.
- **Medallion architecture** — bronze (raw), silver (combined/cleaned), gold (business-ready) layers. In a Lakehouse, typically `/Files` = bronze-style raw data, `/Tables` = curated Delta data.
- **Eventhouse** — stores and queries high-volume real-time event data (KQL databases live inside it).
- **Eventstream** — a Fabric item for ingesting, transforming, and routing real-time streaming data without code (no-code/low-code), e.g. targeting Eventhouse or Lakehouse.
- **Dataflow Gen2** — a low-code/no-code, Power Query-based data transformation tool.
- **Pipeline** — an orchestration tool (Data-Factory-style): schedules and chains activities (including the Copy activity, running notebooks, running Dataflow Gen2).
- **Notebook** — Spark code (PySpark/Scala/SQL/R) for data engineering and transformations.
- **Direct Lake** — a Power BI mode that reads Delta tables directly from OneLake without an import step or DirectQuery latency.
- **Data warehousing glossary**: `dimension table`, `fact table`, `star schema` — the same fundamental concepts as in traditional data warehousing, applied to Fabric Warehouse.
- **Workspace** — the container for Fabric items (lakehouse, warehouse, pipeline, notebook…); bound to a single capacity.
- **Capacity (F-SKU / CU)** — the compute resource a workspace is attached to; the compute of every item in the workspace draws from the same capacity.
- **Domain** — a logical grouping of workspaces by business area (a governance-level concept).
- **Deployment pipeline** — a Fabric-native mechanism for promoting content between dev → test → prod workspaces.
- **Git integration (version control)** — syncing workspace items with a Git repo (Azure DevOps / GitHub) — a different thing from a deployment pipeline, though both fall under "lifecycle management."
- **CI/CD workflow options** — Microsoft's 4 official release-process models ("Choose the best Fabric CI/CD workflow option for you"): **1) Git integration** — Gitflow-style, each stage (dev/test/prod) as its own persistent branch, deployed via the Fabric Git API (`update-from-git`) straight from the repo into the workspace, no build environment. **2) Fabric Items APIs** — trunk-based, a single Main branch, a build-environment script adjusts item definitions (e.g. connectionId/lakehouseId) before deploying via the `fabric-cicd` Python library or the Bulk Import Item Definitions beta API; test/prod workspaces aren't themselves connected to Git. **3) Deployment pipelines** — a Fabric-native low-code option, Git connected only to the dev stage, promotion between dev→test→prod via the deployment pipelines API or UI, supports deployment rules/autobinding (the variable library is now the primary parameterization method, ahead of deployment rules). **4) CI/CD for ISVs** — an extension of option 2, per-customer workspaces only branch off at the prod stage. Many teams mix these (a hybrid), no single choice is mandatory. **DP-700:** `exam-domains.md` explicitly mentions only Git integration and deployment pipelines (options 1 and 3) — options 2 and 4 (Fabric Items APIs, `fabric-cicd`) are "not on the exam" but relevant in real-world practice.
- **OneLake data access roles** — fine-grained (folder/file-level) access control for OneLake data, a separate layer from workspace roles and item-level permissions.
- **Sensitivity label** — a classification tag on Fabric items, inherited from Microsoft Purview.
- **Endorsement** — an item can be marked "Promoted" or "Certified" so users can more easily find trustworthy content.
- **Row-level security (RLS)** — restricts which *rows* a user sees in a Warehouse/SQL analytics endpoint table, enforced in the database tier (not the app). Implemented with an inline table-valued function (predicate, e.g. `WHERE @Param = USER_NAME()`) bound into a `CREATE SECURITY POLICY ... ADD FILTER PREDICATE <fn>(<col>) ON <table> WITH (STATE = ON)`. Filters `SELECT`/`UPDATE`/`DELETE` silently (no error, just fewer/no rows); `INSERT` is unaffected. One security policy per table per operation type. Power BI Direct Lake queries fall back to DirectQuery to respect RLS.
- **Starter pool vs. custom pool** — a recurring Fabric pattern (Spark, Apache Airflow jobs): the **starter pool** is a default, instantly-available pool with fixed sizing that auto-shuts-down after a period of inactivity (good for dev/ad-hoc); a **custom pool** is admin-configured (node size, autoscale, extra nodes), always-on until manually paused (good for production).
- **Spark per-item compute customization** — a workspace-level toggle (workspace settings → Data Engineering/Science → Spark settings → Pool tab → "Customize compute configurations for items"). Off = all Spark jobs use the workspace default pool. On = individual environment items can override runtime version, pool, and driver/executor cores & memory.
- **Domain roles** — **Fabric admin** (creates/edits/deletes domains, assigns domain admins, sees all domains); **domain admin** (business owner of one domain; edits its description/image/contributors, assigns workspaces, can't delete the domain or rename it); **domain contributor** (a workspace admin authorized to assign their own workspaces to the domain).
- **OneLake diagnostics** — workspace-level setting (OneLake settings tab) that streams data-access events (who/what/when, incl. shortcut-originated access) as JSON into a lakehouse in the same capacity, for governance/audit dashboards. Supports immutable (WORM) retention periods.
